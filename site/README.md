# alpi.site

The alpi marketing site and documentation. Vanilla HTML/CSS/JS, built by a
single zero-dependency Node script. Deploys to Cloudflare Pages.

## Layout

```
site/
  templates/        source HTML, CSS, runtime JS (authoring)
  assets/           logos, preview images, the Bricolage font
  scripts/
    markdown.mjs    zero-dep Markdown → HTML renderer
    brand.mjs       the Twin mark, profile marks, live marks, the hero cast, the states list, the
                    footer family, the honeycomb, name tones and the card SVGs, from common/
    copy.mjs        the copy button, its in-place swap and the live announcement
    build.mjs       reads repo docs at HEAD, bakes dist/
  dist/             build output (gitignored, what CF Pages serves)
```

The favicon (`alpi-favicon.svg`), the README card (`alpi-brand.svg`) and the social card
source (`alpi-social.svg`) in `assets/` are generated by the build from `common/`; edit
`scripts/brand.mjs`, not the files. `alpi-social.png` is the one raster, rendered from
`alpi-social.svg` with Bricolage loaded and kept because scrapers reject SVG for `og:image`. The landing's bundler thumbnail
is Twin and the wordmark on the light page ground, also generated by `brand.mjs`. Bricolage Grotesque loads only for the
display steps (the nav wordmark, the hero, page and section headlines) and profile names (`dist/brand.css`); everything
else is Geist.

The favicon, the nav lockup and `alpi-black.svg` / `alpi-white.svg` draw Twin at half turn; the cards draw it in its
held turn. `brand.mjs` builds the same path as `scripts/gen_icons.py`, and the build tests prove the two agree. The
wordmark, the hero and the headings are solid Bricolage Grotesque 800 at -0.04em in the brand ink (cream on night,
ink on paper); profile names take `nameTone` of their accent.

In the landing hero, "agents." is a gradient of the twelve `ACCENTS`, clipped to the text, that flows left in one
seamless 18 em tile every 24 s (CSS only, linear, infinite). Each accent is used as shipped unless it falls under 3:1
on the page ground: then `heroTone` deepens it (light) or lifts it (dark) by the smallest OKLab lightness step that
reaches 3:1, so every frame clears the large-text floor. Reduced motion shows the twelve as one still gradient, forced
colours and print set plain ink, and the flow pauses while the hero is off screen.
Twin in the middle of the cast follows the pointer like the desktop hero mark (`common/gaze.mjs`, copied to
`dist/gaze.js`, versioned like the other scripts): only with a fine pointer, with motion allowed and while the hero is on screen.

The hero is centred: the headline, the lead, the CTA pair (Download for macOS and the install command as a copyable
mono pill), then the cast, then the console on its 20 px card. The cast is the twelve profile shapes in their accents
and Twin in the brand ink, each in a fixed state (`CAST` in `scripts/brand.mjs`), drawn from `common/agentMarks.mjs`
with the apps' CSS motion: the turn and eye parallax per state, the lids and the body. One row at desktop widths
(68 px shapes, Twin 110, sized so the console shows above the fold), three rows around Twin on a phone. Each mark is
named "role · state" and the cast is one tab stop: Tab lands on the first mark, the arrow keys (and Home and End) move
between them, and the tooltip shows the role in its `nameTone` on hover and keyboard focus. The motion pauses while the
cast is off screen and holds the still pose under reduced motion; there is no per-frame script.

Below the hero the landing runs: the four claims (checked, one centred row, one per line on a phone); "Start with one"
with its figure (the reviewer and the librarian working on two machines, an ALP chip between them, the report opening on
the reviewer done, no route lines); "You can tell at a glance", the five states the cast plays drawn as the apps' list;
01 profiles (three cards with 40 px marks in a state their data explains, the grant, one sentence per cell); 02 the five
decisions; 03 ALP (three rungs drawn with the marks and the workgroup honeycomb, the verbs, one line of rules linking the
protocol doc, what ALP is not); 04 "Put alpi to work" (the stage with the desktop window and the phone, then Desktop,
Phone and Terminal and server cards); the questions. Every live mark sits in `.cast` or a `.marks-live` block, pauses off
screen and stands still under reduced motion; a mark beside a visible name is `aria-hidden`.

The stage shots `assets/stage-{desktop,phone}-{light,dark}.png` are rendered from the design kit's drawings by
`python3 design/stage.py` (run it once per desktop or mobile release) and switched by `data-theme`.

The nav is the lockup, the four links and the theme switch; a small Get alpi pill joins it once the hero has scrolled
away, and stays on docs and blog, where it points back to the landing's `#apps`. The phone drawer ends with the same pill.
The footer has three columns (Guides, Reference, Project), signs off with the lockup, the version and the twelve shapes
still, and names GitHub once, as the quiet "source on GitHub" link.

Every copy affordance (the hero install pill, the pull commands, the post install pill, the doc code blocks) is one `copyButton` from
`scripts/copy.mjs`: the copy icon turns into a check and the label reads "Copied" in place for 1.6 s, with no change in
width, and one polite live region announces it. Focus rings are the design system's (2 px, 60 % ink, offset 2) and
show for the keyboard only.

Colour, radii and type come from `common/tokens.mjs`, the same foundations the apps use: the
build writes them to `dist/tokens.css` and every page links it, so the templates hold no colour
literals. Type is Geist on the apps' ladder (`--t-meta` 12 to `--t-display` 28, no text under
12 px) plus two Bricolage display steps (`--t-hero`, `--t-headline`); eyebrows and labels are
Geist 14 in sentence case, never tracked mono caps, and Geist Mono appears only for what a
machine reads (install command, code, paths, keys) at 0.92 em (`--t-mono`). Radii go by role:
pills (`--r-pill`) for everything you press, 12 (`--r-control`) for tags, chips and rail rows,
20 (`--r-surface`) for cards, code blocks and the console, 28 (`--r-sheet`) for the panels that
hold cards, 6 (`--r-xs`) for inline code. There are no rules: space and soft fills separate
sections, cells, steps and questions, with no borders, shadows, blur or gradients. The console
follows the page theme on a 20 px card, and `theme.js` paints `theme-color` from the page
ground of the current theme. The build tests enforce all of it.

The doc pages read like the app: the rail is its sidebar (side ground, 40 px rows of radius 12,
the current page on the selected fill), the title is Bricolage, the meta is Geist with the
version as a code chip, headings are Geist 28 with no rule, and on a phone the doc picker and
"On this page" are pills.

The docs are grouped by `DOCS` in `scripts/build.mjs` (title, group, reading time) into the
index and the doc rail; `docs/ROADMAP.md` is not published, its old URL redirects to GitHub.
The blog index sits in the 760 px reading column, leads with the newest post, lists the rest by year, and writes one
`blog/tag-<tag>.html` page per tag; on a phone the tag row scrolls sideways inside itself. Titles are sentence case. A
post ends on Twin, Download for macOS and the shared copy pill, with "Free for individuals · Read the licence".

Markdown docs live in the repo root (`README.md`, `QUICKSTART.md`,
`CHANGELOG.md`, `LICENSE`) and in `docs/*.md`. They are rendered at
build time into `dist/docs/<SLUG>.html`, so the site always matches the
commit — no runtime fetch, no GitHub API dependency, no CORS.

## Build

```
node site/scripts/build.mjs
```

No `npm install`. Node ≥ 18. Version string and doc list are derived
from `pyproject.toml` and from `DOCS` in `scripts/build.mjs`.

## Preview locally

```
python3 -m http.server --directory site/dist 8000
```

Then open http://localhost:8000/.

## Cloudflare Pages

Production deploys are GitHub Actions direct uploads. Disable
Cloudflare's automatic production branch deploys; otherwise Cloudflare
can publish a commit before the repo checks and release workflows finish.

GitHub configuration:

- Secret: `CLOUDFLARE_ACCOUNT_ID`
- Secret: `CLOUDFLARE_API_TOKEN` with `Account / Cloudflare Pages / Edit`
- Variable or secret: `CLOUDFLARE_PAGES_PROJECT_NAME`

Workflow: `.github/workflows/publish-site.yml`

The workflow fires automatically via `workflow_run` after a successful
`publish` (alpi PyPI release) or `publish-desktop` (desktop release), and
on any push to `main` that touches `site/**`. It rebuilds the static
site and direct-uploads it to Cloudflare Pages with Wrangler. Because
the build reads `pyproject.toml` and `desktop/src-tauri/tauri.conf.json`
straight from the commit that triggered it, the landing page can only
advertise versions that already landed on PyPI / `desktop-latest`.

Cloudflare Pages build settings are only used if you intentionally run a
Cloudflare-side build:

- Build command: `node site/scripts/build.mjs`
- Build output:  `site/dist`
- Root:          repo root
- Env vars:      none

## Updating docs

Edit the source markdown in `docs/` (or at repo root for README /
QUICKSTART / CHANGELOG / LICENSE), rebuild, deploy. Never edit
`site/dist/` by hand — it is regenerated on every build.

To add a new doc to the site: append an entry to the `DOCS` array in
`scripts/build.mjs` (slug, source path, index, category, sub-title).
Order controls prev/next navigation and the docs index.
