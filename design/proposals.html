Proposals · ui-toast.stack · a run of deletes is one toast that counts, and the stack stops at three
UI-TOAST.STACK · desktop · Toasts · Notifications inbox delete and Undo
A run of deletes is one toast that counts, and the stack stops at threeEvery delete in the Notifications inbox raises its own toast with its own Undo (NotificationsModal.jsx onDeleteRow), and the toast stack appends without a cap, bottom-right and growing upwards (Notification.jsx, Notification.module.css), so ten ⌫ presses leave ten pills over the inbox and the composer. The toast pauses on hover but its 5 s delete in useDeleteOutput does not, so a late Undo can only answer “Already deleted”. Recommendation: deletes inside the undo window join one toast that counts them, with one Undo for all, and never more than three toasts on screen. Mobile replaces instead of stacking and loses the earlier Undo: board UI-MOB.TOAST-UNDO.

UI-MOB.TOAST-UNDO · A run of deletes keeps one Undo for all of them02

Proposals · ui-mob.toast-undo · a run of deletes keeps one undo for all of them
UI-MOB.TOAST-UNDO · mobile · Toasts · Notifications delete and Undo
A run of deletes keeps one Undo for all of themThe phone shows one toast at a time and each delete replaces it (Toast.jsx show, app/outputs.jsx onDelete), so after three quick swipes only the last can be undone while the first two still go through when their own 5 s run out. It does not pile up like desktop (board UI-TOAST.STACK), but the earlier Undo disappears without a word. Recommendation: the same batch as desktop, one counting toast whose Undo restores every pending row.
