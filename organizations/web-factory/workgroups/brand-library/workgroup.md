The Brand Library workgroup curates the four brand starters every hotel project picks from: **boutique** (independent, design-led, photography-heavy), **budget** (conversion-focused, transparent pricing), **business** (efficient, corporate guest, meetings), **resort** (family/leisure, gallery and amenity-led). Each starter has a **passport** at `library/starters.md` (who / look / voice / signature structure / photography — this workgroup's canonical definition) and lives in three forms, all in the workspace: the **design source** at `library/wireframes/` (low-fi canvas, 4 styles × 11 pages — open `Hotel Wireframes.html`; `library/README.md` maps the files), the **packaged reference** at `factory/visual-reference.html` (offline render with the bindings toggle), and the **production form** — `templates/hotel-web/src/styles/themes/<name>.css` plus `defaults`/`fontOptions`/`decisionRubric` in `factory/template-spec.json`. Canvas owns the visual layer (tokens + theme CSS coherence with the wireframes), Quill owns the voice layer (per-theme tone, kept in its `hotel-voice-tone` skill), Lingua owns the locale adaptations, Scout feeds demand signals from intakes. Design changes flow wireframes → `template` workgroup decision → template; this workgroup decides WHAT a starter should be, the `template` workgroup lands HOW. The mission is to keep each starter strong enough that a hotel chooses one and only customises 4–6 tokens, never 40. Luxury intentionally stays out — it breaks the factory mindset and is handled as a one-off if a client lands. New starters get added only when intake data shows a recurring segment the existing four don't serve.
